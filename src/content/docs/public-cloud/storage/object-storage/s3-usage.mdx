ZSoftly object storage is S3-compatible. Connect with the regional S3 endpoint, your access key and
secret key, and the bucket's literal name. Direct S3 access does not require a bucket record in the
ZCP control plane. Manage encryption through the S3 API or compatible command-line tools. The portal
UI has no encryption controls.

### Find your bucket name

Use the bucket's literal S3 name. Buckets created through the ZCP control plane receive a numeric
suffix: a requested `my-bucket` becomes something like `my-bucket-001024`. For those buckets, find
the full name with the ZCP CLI:

```bash
zcp object-storage bucket list <storage-slug> --region os-yul --project <project-slug>
```

```
SLUG                NAME                OBJECTS  SIZE (GB)  STATUS
my-bucket-001024    my-bucket-001024    0                   Inactive
```

Use the returned name in place of `my-bucket` below. For a bucket created directly through S3, use
its S3 name without looking it up in ZCP. A control-plane bucket showing `Inactive` with zero
objects is normal until something is written to it.

:::note

The CLI's own bucket subcommands are split. Commands that go through the S3 gateway (`object …`,
`bucket versioning`, `bucket policy`, `bucket lifecycle`, `bucket cors`, `bucket tag`,
`bucket empty`) take the bucket **name**, even though their help text labels the argument
`<bucket-slug>`. `bucket encryption` and `bucket delete` resolve the control-plane bucket slug.
Released ZCP CLI commands still require control-plane instance metadata and key lookup. Use the AWS
CLI or an S3 SDK for direct endpoint access without those records.

:::

### Optional Server-Side Encryption

SSE-S3 (`AES256`) and service-managed SSE-KMS (`aws:kms`) are available in YUL and YOW for new and
existing buckets. Encryption is opt-in. Setting or removing a bucket default changes subsequent
writes only. Existing objects and versions remain unchanged.

Prefer a bucket default so uploads inherit the requested encryption. With your AWS CLI credentials
configured above, set SSE-S3 and read the setting back:

```bash
aws s3api put-bucket-encryption \
  --endpoint-url https://objects.yul.zcp.zsoftly.ca \
  --bucket my-bucket \
  --server-side-encryption-configuration '{"Rules":[{"ApplyServerSideEncryptionByDefault":{"SSEAlgorithm":"AES256"}}]}'

aws s3api get-bucket-encryption \
  --endpoint-url https://objects.yul.zcp.zsoftly.ca --bucket my-bucket
```

For SSE-KMS, use a service-managed key ID provided by ZSoftly:

```bash
aws s3api put-bucket-encryption \
  --endpoint-url https://objects.yul.zcp.zsoftly.ca \
  --bucket my-bucket \
  --server-side-encryption-configuration '{"Rules":[{"ApplyServerSideEncryptionByDefault":{"SSEAlgorithm":"aws:kms","KMSMasterKeyID":"<service-managed-key-id>"}}]}'
```

The access key and secret key authenticate S3 requests. The KMS key ID selects a service-managed
encryption key. Standard S3 permissions apply to both modes.

For a control-plane store, the [CLI tutorial](/tutorials/encrypt-object-storage/) covers active S3
credentials, both bucket defaults, metadata checks, matching downloads, and cleanup with ZCP CLI
v1.3.0. The account bearer token authorizes control-plane requests. The S3 key pair authorizes
object requests.

Enable an SSE-S3 bucket default before the first encrypted upload. Explicit per-object `AES256` can
fail on first use.

For an individual upload, `aws s3api put-object` accepts `--server-side-encryption AES256`, or
`--server-side-encryption aws:kms --ssekms-key-id <service-managed-key-id>`. See the AWS CLI
[encryption configuration reference](https://docs.aws.amazon.com/cli/latest/reference/s3api/put-bucket-encryption.html)
and [upload reference](https://docs.aws.amazon.com/cli/latest/reference/s3api/put-object.html).

:::caution

A single-request copy without encryption settings does not inherit the destination bucket default.
The service refuses single-request copies with encryption headers or an encrypted source. Use
multipart copy or download and re-upload for encrypted copies. Set encryption when initiating a
multipart upload or copy.

:::

### Customer-Provided Encryption (SSE-C)

SSE-C is available through the S3 API on the HTTPS endpoints in YUL and YOW. You supply an AES-256
key with each request. ZSoftly does not store your key.

Generate a key and upload an object:

```bash
(umask 077 && openssl rand -out sse-c.key 32)

aws s3api put-object \
  --endpoint-url https://objects.yul.zcp.zsoftly.ca \
  --bucket my-bucket --key file.txt --body file.txt \
  --sse-customer-algorithm AES256 --sse-customer-key fileb://sse-c.key
```

Send the same key to download the object:

```bash
aws s3api get-object \
  --endpoint-url https://objects.yul.zcp.zsoftly.ca \
  --bucket my-bucket --key file.txt \
  --sse-customer-algorithm AES256 --sse-customer-key fileb://sse-c.key file-copy.txt
```

The `zcp` CLI, the portal, and browser apps cannot send the key, so they cannot read SSE-C objects.
Use the AWS CLI or an S3 SDK.

:::danger

Keep your key safe. An object cannot be read without its original key, and ZSoftly cannot recover
it.

:::

### Common operations

With your client or the AWS CLI configured, use these common operations:

```bash
# Create a bucket
aws s3 mb s3://my-bucket --endpoint-url https://objects.yul.zcp.zsoftly.ca

# Upload a file
aws s3 cp ./file.txt s3://my-bucket/ --endpoint-url https://objects.yul.zcp.zsoftly.ca

# Download a file
aws s3 cp s3://my-bucket/file.txt ./file.txt --endpoint-url https://objects.yul.zcp.zsoftly.ca

# List objects in a bucket
aws s3 ls s3://my-bucket/ --endpoint-url https://objects.yul.zcp.zsoftly.ca

# Delete an object
aws s3 rm s3://my-bucket/file.txt --endpoint-url https://objects.yul.zcp.zsoftly.ca
```

### s3cmd

[s3cmd](https://s3tools.org/s3cmd) is a standalone command-line client for S3-compatible storage.
Install it, then create `~/.s3cfg`:

```ini
[default]
access_key = <access-key>
secret_key = <secret-key>
host_base = objects.yul.zcp.zsoftly.ca
host_bucket = objects.yul.zcp.zsoftly.ca
use_https = True
```

This file holds your secret key, so restrict its permissions:

```bash
chmod 600 ~/.s3cfg
```

Setting `host_bucket` to the same value as `host_base`, with no bucket placeholder, forces the
path-style addressing the service requires. For a bucket in Ottawa, use
`objects.yow.zcp.zsoftly.ca`.

Run the common commands:

```bash
s3cmd ls                                    # list your buckets
s3cmd mb s3://my-bucket                      # create a bucket
s3cmd put ./file.txt s3://my-bucket/         # upload a file
s3cmd get s3://my-bucket/file.txt .          # download a file
s3cmd sync ./local-dir/ s3://my-bucket/dir/  # sync a folder
s3cmd rm s3://my-bucket/file.txt             # delete an object
```

[Create Bucket](/public-cloud/storage/object-storage/create-bucket)
